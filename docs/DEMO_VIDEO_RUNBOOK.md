# ClinPath 课题申报演示视频 · 录屏操作手册

这不是宣传稿，是**录屏当天的操作手册**。目标：5 分钟内从教师视角走完
「班级 → 学生 → 研究数据 → 学生复盘」，每一步都写清点哪里、看到什么、
这一画面要对评审说明什么。

## 0. 录制前 5 分钟检查清单

| 检查 | 命令 / 操作 | 期望 |
| --- | --- | --- |
| 运行版本一致 | `./scripts/verify_deploy.sh` | 输出 `DEPLOY VERIFICATION PASSED`，exit 0 |
| 后端在线 | `systemctl --user status clinical-backend.service` | `active (running)` |
| 前端在线 | `systemctl --user status clinical-frontend.service` | `active (running)` |
| 演示数据在位 | `python scripts/prepare_presentation_data.py --dry-run` | 审计显示 4 名演示学生、日期跨度 ≥ 3 天 |
| AI 可用 | 教师端「系统状态」页 →「测试连通性」 | 显示「可达」 |
| 浏览器 | Chromium 无痕窗口，视口 1440×900 | 无横向滚动条 |

演示对象固定使用 **李明**（`student_no 202601001`）与 **王佳 / 陈晨 / 赵敏**，
不要依赖随机学生 id、随机 session id 或当天临时产生的数据。

登录账号：

```text
教师：见 ~/.config/clinpath/staff-credentials.env 或 e2e-teacher.env
学生：见 ~/.config/clinpath/backend.env 的 SEED_DEMO_STUDENT_PASSWORD
```

**凭证永远不要出现在录屏画面里**：开录前先把浏览器自动填充历史清掉，

## 1. 录制路线（约 5 分钟）

### 第 1 步 · 教师登录（约 20 秒）

打开 `https://clinpath.1031989.xyz/login`，输入教师账号 →
点击「登录并进入系统」。

应该看到：直接落在 **教学驾驶舱**，顶部导航高亮「教学驾驶舱」。

这一画面说明：这是有角色与权限的教学系统，不是匿名工具。

### 第 2 步 · 教学驾驶舱：班级能力热力图（约 30 秒）

不要滚动。画面主体是 **班级能力热力图**，横向铺满整屏，
每行一名学生、每列一项能力，颜色越红越需要干预。

口播提示：班级层面哪一项能力最弱、哪些学生需要优先干预。

### 第 3 步 · 教学驾驶舱：班级能力画像（约 30 秒）

鼠标滚轮下滑一屏，停在 **班级能力画像**：

```text
左侧：九维能力雷达
右侧：共性短板卡片网格（维度 + 等级 + 班级均分）
```

应该看到：页面没有大面积空白，雷达与短板卡在同一屏内。

这一画面说明：班级层面的诊断是可视化、可解释的，不是一张表格。

### 第 4 步 · 学生画像 → 李明（约 40 秒）

点击顶部「学生画像」，在表格中找到 **李明**（注意「当前阶段」显示的是
「阶段N：……」这样的教学语言），点击该行「查看详情」。

应该看到：标题为「李明 学习画像」，副标题给出班级与当前阶段。

### 第 5 步 · 阶段性学习表现趋势 + 学习证据（约 60 秒）

在同一页面：

1. 右上 **阶段性学习表现趋势**：横轴日期、纵轴 0–100 训练得分；
   鼠标悬停任意点，浮层显示日期 / 训练模块 / 训练得分 / 主要能力变化。
2. 下方 **学习证据事件**：每行是一门学习活动，列出训练内容、得分、
   `能力 A 58 → 64（+6）` 形式的能力变化与完成时间。
3. 默认显示最近 10 条，点击「查看全部 N 条学习证据」可以展开完整列表。

这一画面说明：系统记录的不只是分数，而是"哪次训练改变了哪项能力"。

### 第 6 步 · 研究数据（约 45 秒）

点击顶部「研究数据」。画面从上到下：

```text
学生数 / 训练记录数 / 覆盖模块 / 数据时间范围
匿名学生编号 / 班级 / 学习模块 / 训练得分 / 记录时间
当前显示 x / 筛选后 y 条 · 完整研究数据共 z 条
```

可以顺手用「筛选模块」选一个模块，展示表格随之收敛。
最后指出右上「下载完整匿名化 CSV」。

这一画面说明：研究数据默认匿名（只有 `S0001` 这类编号），
页面预览与完整数据集有明确区分。

### 第 7 步 · 切换到学生端（约 15 秒）

点击右上「退出登录」，用学生账号登录（演示账号 `student1`）。

应该看到：落在「学习首页」，导航出现「学习记录」。

### 第 8 步 · 学习记录（约 30 秒）

点击「学习记录」。

应该看到表格：病例名称 / 训练时间 / 状态（已完成）/ 总分 /
评价方式（AI 语义评价）/ 导师互动 N 次 / 操作（查看学习过程）。

这一画面说明：学生可以回来复习自己以前的每一次病例训练。

### 第 9 步 · 历史病例完整复盘（约 60 秒）

点击任意一行「查看学习过程」，进入 `/student/result/{sessionId}`，
向下滚动到 **我的病例推理过程**：

```text
1. 关键信息提取   → 我的最终回答 + AI 导师追问 / 我的回复（聊天气泡）
2. 初步诊断及依据
3. 鉴别诊断
4. 进一步检查
5. 治疗方案
```

演示时刷新一次页面（`F5`），证明内容是服务器上的历史记录，
不是页面临时状态。

这一画面说明：临床思维训练的过程本身被完整保留，可以直接用于复盘教学。

### 第 10 步 ·（如时间允许）真实 AI 训练（约 40 秒）

回到学生首页 →「临床思维训练」→ 打开一个病例，在任一阶段点击
「开始追问」，等待 AI 导师提问，输入一句回复后「继续追问」。

注意：这一步是真实模型调用（DeepSeek Thinking Mode），首次等待可能
10–30 秒。若网络或额度异常，页面会显示「规则降级评价」，此时请
**不要**在视频里声称是 AI 评分 —— 直接跳过这一步。

## 2. 常见故障与处理

| 现象 | 处理 |
| --- | --- |
| 页面出现 `stage_1_...` / `case` 等英文 key | 视为回归缺陷，先修再录（见 ARCH §17.1） |
| 研究数据页出现学生姓名 | 立即停止录制，这是匿名化回归 |
| 学生端看不到「学习记录」 | 该账号没有已完成病例；用 `student1` 或先完成一次训练 |
| 页面转圈超过 30 秒 | 检查 `systemctl --user status clinical-backend.service`；模型调用可能正在排队 |
| 出现 5xx | 记录时间点，查看 `journalctl --user -u clinical-backend.service -n 100` |

## 3. 录屏后自查

```text
1. 教师导航：教学驾驶舱 → 学生画像 → 研究数据，active 高亮正确
2. 画面里没有出现任何开发字段（stage_* / module_type / student_code / created_at）
3. 没有出现学生姓名与匿名编号并排的画面（研究数据页只有编号）
4. 学生端「学习记录 → 查看学习过程」可以在刷新后复现
5. 录制路径与本文档步骤一一对应，没有临时找页面
```
