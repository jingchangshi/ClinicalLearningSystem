## 逐项说明

### R1 为什么必须并列两种设计

分组单位不是措辞问题，它决定三件互不相同的事：

1. **谁被分配**：整班 → 每臂的观测单位是"班次"；班内小组 → 观测单位是"学生"；
2. **统计模型**：整班 → 组别嵌套于班次，必须整群分析；班内小组 → 个体层面模型合法，
   但必须处理同班外溢；
3. **能否推断**：整班 → 每年 20–50 人只有 1–3 个班次，**群数不足**；
   班内小组 → 样本量按人算，但外溢会稀释效应。

v1 只给了第一种，并把它当成默认。这会让教研室以为设计已定，
也会让统计模型在错误的假设下定稿。v1.1 把两种设计并列，并明确
**这是预注册前必须由教研室书面决定的第一项**（E5-01 §13 第 1 项）。

### R2/R3/R6 三处错误的共同根源

v1 把"用稳健标准误"当成了处理一切方差问题的通用手段。
实际上：

- **HC3** 处理的是**异方差**（观测独立、方差不齐）；
- **cluster-robust** 处理的是**群内相关**（观测不独立）；
- **混合模型** 同时处理群内相关并**估计** ICC。

三者不是同一个东西的不同写法。v1 把它们混为一谈，导致：
在整群设计下用个体层面 HC3 → 标准误被低估 → 假阳性；
在单组别批次内估计组间效应 → 参数不可识别。

v1.1 把这三者的适用边界写清楚（E5-02 §2.4），并把整群设计的主分析
改成 cluster-robust / 混合模型（§2.2.1）。

### R4 为什么"每年 20–50 人"必须改变研究定位

`sample_size.py` §[2] 的实际计算（v1.1 重跑）：

| n/组 | 80% 功效最小可检出 d | d=0.5 时的功效 |
| --- | --- | --- |
| 10 | 1.253 | 0.163 |
| 15 | 1.023 | 0.249 |
| 20 | 0.886 | 0.329 |
| 25 | 0.792 | 0.404 |

在每年 20–50 人的规模下，两组等分就是 10–25 人/组。
**25 人/组只能稳定检出 d ≈ 0.8 的大效应。**
这不是"功效略低"，而是"该规模无法支撑一个关于中等效应的确证性结论"。

因此 v1.1 把研究定位明确为**可行性 + 信号生成**，并给出四种在该规模下
实际可交付的设计（E1–E4）。E4（多年累积）是唯一可能达到确证性的路径，
代价是 3–5 年周期——**这个取舍由教研室与科研管理部门决定，文件不预设**。

### R5 为什么主要结局必须是盲评

平台形成性评分不能当主要结局，有三个独立理由：

1. **构念污染**：平台评分与训练内容同源（"教什么考什么"）；
2. **可靠性未验证**：它由规则或模型产生，没有独立的一致性证据；
3. **对照组不存在**：对照组不开放训练模块，平台评分在对照组**没有值**，
   因此根本无法做组间比较。

独立教师盲评避免了这三条：它与训练内容分离、有 ICC 可报告、
两组都有值。v1.1 把这一点写进结局定义（E5-01 §7.0）、分析层级（E5-02 §2.1）、
样本量理由（E5-02 §7.5）与报告清单（E5-02 §10）。

### R7/R8 关于合成数据

`sample_size.py` §[5] 仍会读出合成数据的 d = 3.57。保留这一节是为了
**证明它为什么不能用**，而不是为了使用它。v1.1 做了两件事：

1. 在脚本开头与各节标题声明"所有 d 都是示例假设"；
2. 把 §[5] 的措辞从"不能用于样本量规划"改为"**禁止**用于任何样本量规划或功效陈述"。

SAP §8 同步强化，并明确指出：§7 中出现的 d = 0.4–1.0 是**独立的示例假设**，
与演示数据无关。
