# E5-03 伦理与隐私方案

> **状态：伦理审查**申请要点**草案，尚未提交、尚未获得批件。**
> 本文件不预设伦理批件号、受理时间或委员会名称——这些必须由依托单位在受理后给出。
> 本文件不声称任何真实学生已参与，也不声称任何专家审核已完成。
> 合成演示数据（`SYNTHETIC_DEMO_NOT_REAL_STUDENTS`）不涉及人类受试者，
> 不构成伦理审查对象；它只是本方案中"数据处理流程已可运行"的技术证据。

## 1. 研究性质与伦理定位

| 项目 | 内容 |
| --- | --- |
| 研究类型 | 教育干预研究（教学法比较），非临床试验 |
| 研究对象 | 本科医学生（成年人），**不涉及患者**。主研究总体 = 风湿免疫本科见习 **7 天/批 × 7 人/批 × 7 批 = 49 名见习学生**；另有 21 名实习阶段学生为**独立扩展人群**（见 §2.5） |
| 是否涉及患者数据 | **否**。研究不使用任何患者可识别信息；教学病例为教研室既有教学病例或经脱敏的教学材料 |
| 风险等级 | 低风险（minimal risk）。主要风险是**学业负担**与**隐私**，不是身体风险 |
| 审查类型 | 建议按**免除知情同意签署的例外**或**简易审查**申请，最终由伦理委员会决定（`待确认`） |
| 是否需要临床试验注册 | 教育研究通常不需要；但**建议预注册**（ChiCTR 或 OSF），以提高方法学可信度 |

> **为什么不是"免除审查"**：研究涉及可识别的人类受试者数据（学号连接表），
> 即使风险很低，也应提交审查。是否可走简易审查由委员会判断。

## 2. 伦理审查申请要点（逐条对应委员会关注点）

### 2.1 研究目的与科学价值

- 目的：评价在本科风湿免疫见习中引入**分步形成性训练**是否改善学生在
  独立标准化病例上的临床推理表现；
- 价值：若有效，可为见习教学提供可复制、可追踪的形成性训练方式；
  若无效或有害，同样是重要信息（避免推广无效教学法）；
- **明确声明**：本研究不以患者诊疗为对象，不产生临床决策建议。

### 2.2 研究设计与对照的伦理

| 问题 | 回答 |
| --- | --- |
| 对照组是否被"剥夺"了可能有效的教学？ | 对照组接受**现行常规 CBL**，即当前教学标准；不是"无教学"。研究结束后，对照组**可延迟获得**平台训练权限（建议写入方案） |
| 干预是否增加学生负担？ | 训练在既有 7 天见习课时内完成，**不额外增加**课时；最低训练剂量见 `E5_01` §5.2，具体由教研室确认 |
| 是否影响课程成绩？ | **否**。参与与否、分组、平台表现均**不进入**课程成绩。此点写入同意书 |
| 是否存在强制？ | 带教教师不得以任何方式施压；由不参与教学的第三方（如教研室教学秘书）负责招募与同意 |

### 2.3 风险与受益

| 类别 | 内容 | 处理 |
| --- | --- | --- |
| 身体风险 | 无 | — |
| 心理风险 | 学生可能因"被分到对照组"或"平台表现不佳"感到压力 | 明确说明分组方式（**整个 7 人批次作为一个整体，随机分配到 ClinPath 组或常规 CBL 组**，按预注册）、与能力评价无关；平台反馈为形成性、非成绩 |
| 社会风险 | 同学间比较 | 平台数据仅本人与教师可见；研究数据去标识 |
| 隐私风险 | 学习行为数据被记录 | 数据最小化 + 去标识 + 访问控制（§4、§5） |
| 受益 | 干预组获得额外形成性反馈；所有参与者获得研究结果摘要 | 对照组延迟开放 |
| 风险受益比 | 低风险、潜在教育受益 | 可接受 |

### 2.4 弱势群体

- 本科生为成年人，**不属于**典型弱势群体；
- 但**学生与教师存在权力关系**，属于"依赖关系"情形，必须：
  - 由非任课教师执行招募与同意；
  - 明确"拒绝/退出不影响成绩、不影响带教评价"；
  - 同意书用平实语言，避免"不参加会影响学习"的暗示。
- 不纳入未成年人；若出现未满 18 岁者，默认排除并按委员会要求处理。

### 2.5 两个研究人群（**伦理申请必须分别说明**）

| 人群 | 规模 | 是否纳入主结局分析 | 说明 |
| --- | --- | --- | --- |
| **主研究总体** | **49 名本科见习学生**（7 天/批 × 7 人/批 × 7 批） | **是** | 本伦理申请的主体 |
| **扩展人群** | **21 名实习阶段学生** | **否** | 独立分析或仅描述，**绝不并入主结局** |

- 扩展人群的**确切学段**及**是否与 49 名见习学生完全重叠**目前 `待确认`；
- 若涉及扩展人群，须在伦理申请与同意书中**单独说明**其人群定义与用途，
  并明确"不与主研究合并"；
- 在扩展人群的学段与关系确认之前，**不采集**其研究数据。

## 3. 知情同意

### 3.1 同意流程

```
教学秘书（非任课教师）在 D1 前集体说明（约 10 分钟）
        ↓
发放纸质/电子同意书（版本号 ICF-v1.0）
        ↓
学生独立阅读，可提问，可带回考虑 ≥ 24 小时
        ↓
签署 或 拒绝（拒绝不记录原因，不影响任何教学安排）
        ↓
签署者分配 study_id；拒绝者不进入研究数据集
```

### 3.2 同意书必须包含的要素

1. **研究题目与目的**（用非专业语言）；
2. **为什么邀请你**（你是本届风湿免疫见习学生）；
3. **如果你参加，会发生什么**：D1 考核、D2–D5 训练期（常规 CBL 或 ClinPath）、D6 考核、
   预计额外时间（`待确认`，应尽量为 0）；
4. **分组方式**：**整个 7 人批次作为一个整体，随机分配到 ClinPath 组或常规 CBL 组**
   （**同一批次内所有同学接受同一种教学，不会把同批同学分成两组**）；
   **以伦理批件与预注册为准**，你**不能选择**组别；
5. **风险与不适**：主要是时间投入与可能的压力；
6. **受益**：不承诺成绩提升；对照组可在研究结束后获得平台权限；
7. **自愿与退出**：可随时退出，**不影响课程成绩、不影响带教评价、不需要理由**；
8. **隐私**：收集什么数据、如何去标识、谁可以访问、保存多久、如何销毁；
9. **AI 使用说明**（§6）；
10. **数据可能用于论文/报告**，但以**汇总、去标识**形式；
11. **联系人**：研究负责人、伦理委员会联系方式（`待填写`）；
12. **同意声明与签名栏**（学生、执行人、日期；如需见证人则加见证人栏）。

### 3.3 同意书版本管理

- 版本号写入 `consent_log.icf_version`；
- 版本变更（如新增数据字段）必须**重新征得同意**；
- 已签署的旧版本同意书原件保留，不销毁。

### 3.4 电子同意的额外要求（如采用）

- 使用单位批准的电子签名平台；
- 记录签署时间戳、IP（仅用于审计，不进入研究数据集）；
- 提供可下载的同意书副本。

## 4. 数据最小化

### 4.1 只收集研究问题必需的数据

| 收集 | 不收集 |
| --- | --- |
| 匿名研究编号 | 姓名、学号（连接表除外，单独存放） |
| 组别、批次、批次起止日期 | 家庭住址、电话、邮箱 |
| D1/D6 在线考核答卷与双评分六维度 | 既往病史、心理健康信息 |
| 训练过程（步骤、追问、修订） | 设备指纹、精确地理位置 |
| 参与度（完成次数、用时） | 社交媒体、其他平台行为 |
| 同意状态与日期 | 身份证号、照片、签名图像（签名只在纸质原件） |

### 4.2 明确不收集的内容

- **不收集**学生对本课程/教师的主观评价（避免与成绩评价混淆）；
- **不收集**任何患者数据；
- **不收集**与教学无关的个人信息。

### 4.3 数据字段的"必要性"论证（申请书中逐项说明）

每个字段在 `E5_protocol_data_dictionary.md` 中都有"用途"说明；
申请书应附一张"字段—用途—是否必需"表，供委员会审阅。

## 5. 去标识化流程

```
平台数据库（含 student_id, 姓名, 学号）
        │
        │  ① 导出：只走 /api/teacher/export/research-data.csv
        │     该路径只输出 S<student_id:04d> 与班级，不输出姓名
        ▼
去标识导出（S0001 等）
        │
        │  ② 映射：S0001 ↔ study_id（R-2027-001）由研究负责人建立
        │     连接表单独加密存放
        ▼
研究数据集（study_id + 研究字段）
        │
        │  ③ 分析：只用 study_id
        ▼
分析结果（汇总统计）
```

### 5.1 三级标识

| 级别 | 内容 | 存放 | 访问 |
| --- | --- | --- | --- |
| L1 直接标识 | 姓名、学号 | 平台 `students` 表 / 连接表 | 平台管理员、研究负责人 |
| L2 假名 | `study_id`（`R-...`） | 研究数据集 | 研究团队 |
| L3 匿名 | 汇总统计、图表 | 论文/报告 | 公开 |

### 5.2 去标识的技术保障（已实现，可引用）

- 平台**唯一出口** `app/core/deidentify.py` 在 `llm_service.prompt_json()` 与
  `OpenAICompatibleClient.chat()` 两处强制脱敏，覆盖手机号、邮箱、身份证、
  住院号/门诊号/MRN、带标签姓名等；**只记录命中类型，绝不记录被脱敏的值**；
- 教师录入真实病例时，`POST/PUT /api/teacher/cases` 返回
  `deidentification: {clean, findings:[{field, kinds}], message}`，
  只报告**哪些字段、哪类标识**，不回显标识值；
- 学生端 API 不返回 `standard_diagnosis`、`treatment_plan`、`rubric`、SP 隐藏病史；
- 研究导出只输出匿名编号。

> **已知限制（必须写入申请书）**：无标签的自由文本姓名无法在不误伤临床症状的前提下
> 可靠识别，应在输入边界（教师录入）处理。本研究不使用真实患者文本，
> 因此该限制对本研究影响很小，但平台在真实病例录入场景下仍需人工复核。

### 5.3 去标识后的再识别风险

- 小样本 + 细粒度变量（如"某批次唯一一名缺席者"）可能间接识别；
- 对策：报告中**合并**过细类别（如批次、日期只到月）；
- 不发布任何单元格 n < 5 的交叉表。

## 6. AI 使用声明

### 6.1 AI 在本研究中的角色

| 用途 | 是否用于 | 说明 |
| --- | --- | --- |
| 形成性追问（导师） | 是 | 按步骤生成聚焦问题，**不透露**标准诊断/治疗/量表 |
| 形成性反馈 | 是 | 训练后反馈，非成绩 |
| **主要结局评分** | **否** | 主结局由两位真实教师盲评 |
| 次要结局评分 | 否 | 同上 |
| 自适应推荐 | 是（过程） | 规则优先，LLM 只改写解释措辞；推荐本身不由 LLM 决定 |
| 教学数据分析 | 否 | 统计分析不使用 LLM |

### 6.2 AI 可能不可用

- 平台设计为**可降级**：模型不可用时自动使用规则反馈，
  并在 `evaluation_mode` / `reason_source` 中标记 `rule_fallback` / `rule`；
- **绝不**把规则输出呈现为 AI 输出；
- 研究将记录 AI 降级比例（来自 `ai_invocations`），作为可行性指标；
- 若降级比例过高（如 > 30%，`待确认`），干预组的"AI 辅助"实际强度不足，
  必须在报告中说明，且不得把结果解释为"AI 教学无效"。

### 6.3 数据是否发送给模型提供商

- 发送内容：**教学病例文本 + 学生作答**（均不含患者可识别信息）；
- **不发送**：姓名、学号、`study_id`、评分、组别、研究设计信息；
- 出口处强制脱敏（§5.2）；
- 每次调用留 `ai_invocations` 审计事件（只含元数据与证据引用，
  **不含 prompt / response 正文**）；
- 提供商的数据保留政策与部署地区，须在申请书中说明（`待确认`具体条款）。

### 6.4 AI 输出的使用边界

- AI 反馈是**形成性**的，不进入成绩；
- AI 不参与"是否通过""是否合格"的判断；
- 学生可查看 AI 反馈，但教师保留最终解释权；
- 若学生发现 AI 反馈有误，可向带教教师反馈，不影响评价。

### 6.5 对学生的影响与告知

同意书必须用一段话说明：
> "本平台使用人工智能生成部分追问与反馈。AI 可能出错，其反馈仅供学习参考，
> 不作为成绩依据。平台在 AI 不可用时会改用预设规则反馈，并会明确标注。"

## 7. 数据泄露应对

### 7.1 分级

| 级别 | 情形 | 响应时限 |
| --- | --- | --- |
| 一级 | 去标识研究数据集（仅 `study_id`）泄露 | 24 小时内评估，72 小时内报告 |
| 二级 | 连接表（`study_id ↔ 学号`）泄露 | 立即（2 小时内）启动响应 |
| 三级 | 同意书原件/签名泄露 | 立即启动，按单位信息安全事件上报 |

### 7.2 响应流程

```
发现 → 立即隔离（断开访问、保留日志）
     → 评估范围（哪些数据、多少人、是否可识别）
     → 报告：研究负责人 → 单位科研管理部门 → 伦理委员会
     → 通知受影响学生（如涉及可识别信息）
     → 补救（改密、撤销访问、必要时重新征得同意）
     → 记录：事件报告、根因、改进措施
```

### 7.3 预防

- 连接表加密、单独存放、仅负责人可访问；
- 研究数据集不放在个人电脑桌面/网盘；
- 导出文件带来源标记与生成时间，便于追溯；
- 定期（建议每学期）审计访问日志；
- 团队成员签署保密承诺。

## 8. 学生拒绝参与的替代评价方式

**核心原则：参加研究与否，绝不进入课程成绩。**

| 情形 | 替代安排 |
| --- | --- |
| 拒绝参加研究 | 正常参加见习与常规 CBL；不参加 D1/D6 研究考核；课程考核按教研室既有方案执行 |
| 参加后退出 | 已完成的训练不影响成绩；后续按常规见习执行；已采集数据按同意书约定处理 |
| 分到对照组 | 接受常规 CBL（现行标准）；研究结束后可申请平台训练权限 |
| 因技术故障未能完成训练 | 不视为学生责任；记录为方案偏离；不影响成绩 |

**实施要点**

- 课程成绩的评定标准、考核方式在研究开始前**书面固定**，且**不引用**研究数据；
- 任课教师不知道（或不需要知道）谁参加了研究；
- 同意/拒绝名单由教学秘书保管，不交给任课教师。

## 附：独立在线考核的隐私与伦理补充（终稿轮，2026-10-18）

> 状态：**草案要点，尚未提交伦理、尚无批件、不预设批件号。**

1. **答卷内容**：D1/D6 在 ClinPath 独立在线考核模块内作答，答卷与评分存放在 Assessment 域，
   与形成性训练数据分表存放；研究分析使用研究编码，真实身份映射表另行限制访问。
2. **去标识**：作答说明须明确禁止学生在答案中写入姓名、学号等身份信息；
   系统**不能**把学生自行写入答案的信息当作已匿名化，须在评分前由研究人员做必要的去标识检查。
3. **盲法风险**：若评分教师同时带教该批，则可能知道学生所属教学组；须记录并由研究负责人
   安排独立评分人员，不得在报告中宣称「完全盲法」。
4. **不计成绩**：D1/D6 研究考核不计入课程成绩；拒绝参加者不受影响（见 §知情同意）。
5. **AI 边界**：独立考核期间不调用 AI 追问、不产生 AI 评分；训练阶段的 AI 使用见 §6。
6. **题本保密**：知情同意与伦理材料应写明题本保密要求（同批、跨批均不得外传 D1/D6 题目），并设泄漏事件登记；该要求不能靠系统权限强制，见 `E5_01` §9.1。
7. **伦理状态**：截至 2026-10-18，伦理审查**尚未提交**，**无批件**；批件号、受理编号只能在
   依托单位伦理委员会给出后由真实人员填写：【待填：伦理委员会名称、受理编号、批件号、批件日期】。
   在批件（或书面豁免确认）取得之前，**不得开始任何真实学生数据收集**。
