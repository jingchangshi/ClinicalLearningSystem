## 3. "实质性新临床资料与推理路径"的最低要求（反"换皮"）

任务书 §5.3(7) 明确：**不只是更换姓名和化验数值**。以下各项必须逐项由作者说明"新在何处"，并由教师复核：

| # | 要求 | 反例（不满足） |
| --- | --- | --- |
| R1 | 患者代号、年龄取整、性别、起病时间线、就诊场景与旧稿**不同** | 同一患者 E、同一年龄、同一"8 个月"病程 |
| R2 | 主诉与现病史的**叙述结构**不同（信息组织方式、阴性信息的落点） | 旧稿句子改写同义 |
| R3 | 关键化验/检查**数值与组合**不同，且**决定性证据换成另一条线索**（改变"哪一项发现定调"） | 同一抗体、同一滴度、同一影像结论 |
| R4 | 鉴别诊断的**活跃分支**不同：至少两个竞争诊断在阶段间真实存在竞争，且其排除依据是新资料 | 旧稿的鉴别列表原样保留 |
| R5 | 所依据的分类标准/指南的**使用方式**不同（套用哪一条、计分如何影响结论、哪里"不满足"） | 同一计分表逐项复述 |
| R6 | 阶段间**信息（不）完整性设计**不同：哪些信息在 S1 被刻意省略、在哪个阶段才出现、以及"未评估项"的位置 | 五阶段内容按旧稿顺序平移 |
| R7 | 六维评分锚点**重新撰写**，且锚点对应到新资料的可观察行为（不是把旧锚点套到新数值上） | 锚点文字微调 |
| R8 | 与**训练库不重叠**：不得与 SLE、RA、AAV、IIM 及种子病例（SLE 合并感染、成人 Still 病等）同病种同推理链；不得有"直接背出诊断"的捷径 | 疑似 SLE→训练病例答案抄一遍 |

**可测量的筛查指标（辅助，不作为通过标准）**：把新稿的五阶段 `clinical_information` 合并为文本，与旧稿做 4-gram 相似度比较。
参考量级：**两份互不相干的题本（现行 A01 草案 vs A02 草案）** 的 4-gram Jaccard ＝ 0.046、containment ＝ 0.091。
新稿的同类指标应停留在同一量级（建议 containment **< 0.15**，且不得出现与旧稿共有的长片段）；指标偏高必须由作者与教师解释。
复核命令（在仓库根目录执行，只读取两个文件，不修改任何内容）：

```console
$ python3 -I -c "
import importlib.util, json, sys
spec=importlib.util.spec_from_file_location('a','scripts/grant/audit_exam_leakage.py')
m=importlib.util.module_from_spec(spec); sys.modules['a']=m; spec.loader.exec_module(m)
def text(p):
    d=json.load(open(p,encoding='utf-8')); return '\n'.join(s['clinical_information'] for s in d['stages'])
old=text('docs/.../A01_assessment_payload_DRAFT.json')   # 旧稿（已公开）
new=text('<私有路径>/A01_SECURE_V1/form.json')            # 新稿（不在仓库内）
print('jaccard', round(m.jaccard(old,new),3), 'containment', round(m.containment(new,old),3))
"
```

> **该指标看不懂"换了说法、同一推理链"**（泄漏审计 §6 的同一条局限）。是否"实质性更新"最终由**两位真实教师**判断，
> 并在审核表中逐条回答 §5 的 G 类问题。

**合成与脱敏要求（沿用平台既有规范）**：虚构合成病例；患者用字母代号；年龄取整；相对时间描述；
不含真实姓名、学号、住院号、手机号、身份证等任何标识；不含无指征免疫抑制的诱导性提示；
治疗只写原则层面。撰写过程中不得把真实患者资料带入任何文件。

## 5. 审核门禁（发布前必须全部满足）

1. **两位不同的真实风湿科教师**独立审核；**作者不得自审**（平台 `forms.py` 强制：`two_approvals_required`）。
2. 审核对象是**同一个内容哈希**；审核后改动内容则审批作废，必须重新审核（平台 `form_content_sha256` 绑定）。
3. 审核表必须逐条回答（在现有 A—E 类之外新增 G 类）：
   - G1 与**旧公开稿**相比，R1—R7 各条新在何处？请逐条写出（若某条未变，说明理由）。
   - G2 是否只是"换皮"（同一推理链、同一决定性线索）？若为是，**不得通过**。
   - G3 与**训练库**（SLE/RA/AAV/IIM 及种子病例）是否存在同病种、同推理链或答案捷径？如何处理？
   - G4 与**生产实际病例目录**是否重叠？（该目录**至今未核查**，见泄漏审计 L-6/渠道 P——需先取得脱敏导出版本）
   - G5 分类标准/指南的引用是否可核实？无法核实的引用必须删除（旧清单 H21 的同类问题）。
4. 平台层面：`review_status = APPROVED_FOR_ASSESSMENT` 之后才可分配场次（`require_published` 在三处生效）。
5. **不得提前写"已审核"**：在教师签署之前，所有文档只能写"待真实教师审核"。现有公开稿的 `PENDING_REAL_REVIEW` 状态同样未变。

## 6. 命制期间的保密要求

- 草稿**只能**放在私有受控环境（`EXAM_SECURE_IMPORT_SPEC.md` §3），**不得**提交到公开仓库，不得粘贴进聊天工具或公开云盘。
- 提交前运行 `python3 -I scripts/grant/publish_safety_scan.py --scope staged`；出现 `BLOCK` 即停止提交。
- 训练侧 AI 病例生成器没有"考核主题禁用清单"（泄漏审计 L-5）：命制期间应由课题组在 SOP 中明确
  **禁止用教师端生成器批量生成"未分化关节炎/干燥综合征"训练病例**，以免把考核主题带进学生可见的训练库。
- 作者、审核教师与导入执行人不得在公开渠道讨论题本内容；泄漏事件按 `EXAM_SECURE_IMPORT_SPEC.md` §6 处理。

## 7. 现有工具能做什么、不能做什么

| 工具 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| `validate_assessment_payloads.py` | 五阶段结构、字段与锚点格式的技术校验 | 不判定医学正确性（脚本头已声明） |
| `audit_exam_leakage.py`（含 `--channels`） | 扫描仓库内学生可见内容与两旧稿的重叠；区分五类泄漏渠道 | 读不到仓库外的新稿与图片内部文字 |
| `audit_exam_leakage.py --extra-json` | 纳入生产库的**脱敏目录导出**（渠道 P） | 需要有人从生产库导出；**目前未提供，因此未核查** |
| `publish_safety_scan.py` | 推送前拦截未公开题本/答案/锚点/真实数据进入公开提交 | 看不到仓库外文件，不能撤销既往暴露 |
| §3 的 4-gram 相似度命令 | 新稿与旧稿的"照抄程度"筛查 | 看不懂"换说法、同推理链" |
