### 3.1 填写流水线已就绪（ZIP 到位后是「一条命令」的事）

本轮把 §7.3/§7.6 的填写与核验做成了**可执行的脚本**，而不是只写在文档里的步骤：

| 脚本 | 作用 | 现在（无官方原件）的实际行为 |
| --- | --- | --- |
| `scripts/grant/fill_official_forms.py` | 按**官方表单自己的标签**定位六栏与汇总表字段，把 `E5_04_application_text.md` 的正文与已知字段写进**官方模板的副本**，输出到私有目录 | **拒绝运行，退出码 2**，打印缺少的两个文件路径；不生成任何替代模板 |
| `scripts/grant/validate_official_docx.py` | 对产出的 DOCX 执行 §7.6 的核验，每项报 PASS / FAIL / **SKIPPED（附原因）** | 可用于任何 DOCX；本机无渲染器时 PDF 目视项如实标 SKIPPED |

**ZIP 到位后的确切命令（两条）**：

```bash
# 1) 把申请人给的 ZIP 原样放到（文件名保持官方原名；也可用 --zip 指定任意路径）
#    docs/teaching_grant_2026/APPLICATION_PACKAGE/official/ClinPath_2026_Official_Source_Templates.zip
#    （已解压好两个 .docx 也可以，脚本按文件名自动识别；三种方式见 §3）

# 2) 填写 + 核验（脚本自行从 ZIP 取出附件2/附件3）
uv run --python 3.11 --with python-docx python scripts/grant/fill_official_forms.py
uv run --python 3.11 --with python-docx python scripts/grant/validate_official_docx.py \
    "docs/teaching_grant_2026/APPLICATION_PACKAGE/official_out/浙江省2026年教改项目申报书_官方模板填写版.docx" \
    --template "docs/teaching_grant_2026/APPLICATION_PACKAGE/official/附件2_教学改革项目申报书.docx"
```

> 第二条命令的 `--template` 用于比对页边距；若官方原件只在 ZIP 里，可先解压附件 2 到该路径，
> 或省略 `--template`（该单项将如实标 SKIPPED）。

**这一条命令会产出**（私有目录 `APPLICATION_PACKAGE/official_out/`，已在 `.gitignore` 排除）：

- `浙江省2026年教改项目申报书_官方模板填写版.docx`（六栏正文 + 已知字段已写入官方版式）
- `浙江省2026年教改项目申报汇总表_官方模板填写版.docx`（汇总表已知字段已写入官方版式）

**它不会**产出：`主持人教学简历_待核对.docx`（需真实教学资历与荣誉证明，属真人事项）。

填写脚本的硬规则（均已由测试覆盖）：

1. 官方原件缺失 → **退出 2**，不生成任何文件；错误信息**列出所有已查找的位置**与三种指定方式，
   并说明「已找到的内容」（例如 ZIP 里只有 `.doc` 时直接说明「不是 .docx」）；
2. **ZIP 单独就够**：只解压附件 2/附件 3 到仓库外的临时目录，运行结束即删除；
   通知与附件 1 只报告、不落盘；成员按扁平化文件名读取，构造的成员路径无法逃出临时目录；
3. 输入文件带本仓库「非官方模板」横幅 → **退出 6**，绝不把自己的草稿当官方模板填；
4. 找不到某个预期字段 → **逐个列出为缺失（退出 3）**，不静默跳过；加 `--write-partial` 才写出已匹配部分；
5. 目标格已有内容 → **报冲突（退出 7）**，不加 `--overwrite` 不覆盖；
6. 某栏超过官方上限 → **退出 4**，不写出；
7. 标签由 `--field-map` 的 JSON 提供：官方模板若写「课题名称」而非「项目名称」，改 JSON 即可，不改代码。

**§7.6 核验项与本机可执行性（2026-10-19 实测）**

本机实测：`libreoffice`、`soffice`、`pandoc`、`pdftoppm`、`pdftotext` **全部不存在**；
`python-docx 1.2.0` 可用（经 `uv run --with python-docx`）。

| §7.6 核验项 | 脚本检查 | 本机实测结果 |
| --- | --- | --- |
| 字数核验 | 逐栏非空白字符计数，比对官方上限**与** E5_04 自身计数（转录丢失/重复都会被抓到） | **真实 PASS/FAIL** |
| DOCX 重新打开 | zip 必需部件（`[Content_Types].xml`、`word/document.xml`）+ python-docx 重新打开并读回段落 | **真实 PASS/FAIL** |
| 页边距 | 逐节读取上/下/左/右边距，必须显式设置且为正 | **真实 PASS/FAIL** |
| 页边距与官方模板一致 | 给 `--template` 时逐节比对官方原件 | 给模板则**真实 PASS/FAIL**；未给则 SKIPPED（附原因） |
| 表格完整性 | 枚举所有表格（含嵌套），按 `gridSpan` 计算每行有效单元格数，须等于表格网格列数 | **真实 PASS/FAIL** |
| 跨页（结构层面） | 表格内显式插入的分页符；多行表格是否设置 `w:cantSplit` | **真实 PASS/FAIL** |
| 中文字体与字号 | 每个含中文的 run 回溯 run → 段落样式 → 字符样式链，要求有显式东亚字体与字号，并输出字体/字号分布 | **真实 PASS/FAIL** |
| 提交就绪 | 全文是否仍含 `【待填` | **真实 PASS/FAIL**；真人填毕前**预期为 FAIL**，它拦的是提交，不是本流水线 |
| **跨页：PDF 渲染目视检查** | 探测渲染器后调用 | **本机无法执行** → 固定文案 **SKIPPED**：`no libreoffice/pandoc on this machine; requires a human render check`，并打印人工复核命令 |

**渲染类核验（实际分页位置、表格跨页断点、中文字体真实渲染效果）本机一律不做**，
报告中标为 SKIPPED 且**不计为通过**；需由真人在装有 LibreOffice/Word 的机器上执行：

