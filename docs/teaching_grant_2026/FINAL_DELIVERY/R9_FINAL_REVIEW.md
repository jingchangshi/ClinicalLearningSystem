## 2. P0-1：CBL 组训练访问隔离

**实现**：新增单一策略函数 `backend/app/research/study_access.py`（`access_for` / `require_training_access` /
`require_student_self_training_access`），由训练入口复用；**未引入权限框架、未新建用户体系**。

判定顺序（每条都由测试固定）：

| 情形 | 判定 |
| --- | --- |
| 未纳入研究 | 放行（研究外学生完全不受影响） |
| 已入组但整批分组**尚未冻结** | 放行，且**不推断**组别（§3.3.10） |
| 冻结为 `clinpath` | 放行 |
| 冻结为 `cbl` 且批次教学窗口**未结束** | **拒绝** |
| 窗口无日期（`undetermined`） | **保持关闭**——已冻结即为研究学生，缺窗口证据时默认放行等于按猜测开放干预 |
| 窗口已登记结束 | 放行（此后按预先确定的教学方案） |

**受保护入口**：`POST /api/sessions/start`（拒绝发生在写入会话行**之前**）、`/answers`、`/coach`、
`/tutor`（读写）、`/submit`、`GET /result`，以及 `/api/student/{pathway,competency,dashboard,history}`。

**关键性质**：

- **旧会话不能绕过**：门控按**学生当前状态**判定，而非会话创建时间。测试先在窗口关闭期让 CBL 学生
  完整训练并提交，再开窗，断言**每一条**续接与读取路径都被拒。
- **拒绝不泄漏分组**：`{"detail":{"code":"study_training_restricted","message":…}}`，
  message 不含组别、批次或研究编码（有子串扫描测试）。
- **刻意不拦截**（§3.3.7，避免误封教学资源）：会话外壳 `GET /sessions/{id}`（病例材料＋本人未评分作答）、
  病例库、knowledge / guidelines / skills / SP，以及**全部独立考核接口**。
  有一个测试在同一登录会话内验证「T0 可完成 ＋ 训练被拒」。
- **`cases.py` 未改动**：它只有只读浏览与教师建题助手，**没有干预入口**，改它没有意义。
- **教师/管理员审计视图保留**：按 id 的学生路由仅当请求者**本人**是该学生时拦截。

**发现并修复的集成交互**（真实问题，非我方引入）：CBL 隔离上线后，R8.2 研究流程的浏览器用例开始
返回 403 —— 因为该用例假定 `student_ids[0]` 属于 ClinPath 组，而冻结抽取把 `TEST-C01` 分到了 **CBL** 组。
**策略是对的，是用例"组别盲"。** 已改为从产品自身的分配记录读取组别并改用 ClinPath 批次，
且缺失组别信息时用例**显式失败**而不是静默降级。这一交互只有在真实集成时才会暴露。

## 3. P0-2：Research 与 Training 过程证据关联

**实现**：新增只读关联层 `backend/app/research/linkage.py` 与 CBL 教学过程登记
`backend/app/research/teaching_log.py`（受控 JSON，默认在 `~/.config/clinpath/`，可用环境变量指定；
**真实教师姓名与主题不得进入公开仓库**）。

- `training_exposure`、`intervention_count`、`cbl_case_topics` 现在**来自真实行**；
- 每条记录另带 `linkage`（完成病例数、五阶段次数、AI 导师调用、按任务分类的规则降级、
  每次训练六维分与评分来源、D4/D5 推荐及完成情况、教师干预、实际训练窗口、`missing` 缺口清单）
  与 `sources`（五类来源）；导出与冻结快照新增 `provenance`（含 `linkage_version` 与教学登记 sha256）；
- **缺失一律给 `None` ＋ 原因**：不转 0、不虚构干预；**未登记的 CBL 教学不等于"没有教学"**；
- **只读**：不写行、不调用训练服务、不重算分数；不含生成时间戳，故同一数据库状态总是产生相同冻结字节；
- `cohort_stats.student_scores_from_export` 使统计函数可直接接受真实导出形状，而非只支持静态合成 CSV。

**发现并修复的真实缺陷**（导出链契约不一致，由后端成员报告、牵头成员核实后要求修复）：

`dataset.py` 发出的 `assessment_form_id` 是**数据库记录 id**，而 `dataset_export.build_rows` 拿它
与 `FORM_BY_ORDER` 的**槽位码**（`A01`/`A02`）比较。两者对同名字段的定义不一致，因此
**"工作导出 → CSV 冻结"这条链在真实题本 id ≠ 1/2 时必然失败**，而当时的测试恰好用 id 1/2 并通过
显式映射绕过了它。修法（不改变既有语义）：拆成两列 —— `assessment_form_id`（记录 id，可追溯）
与 `assessment_form_slot`（`A01`/`A02` 槽位，**冻结顺序校验的唯一依据**），并新增
"用非 1/2 的真实题本 id 走完整导出→冻结链路"的端到端测试，而不是继续绕过。

## 8. §8.4 原有 3 项 Playwright 失败：已分类、已修复、不再跳过

上一轮把三项失败留作失败，理由是"重建演示数据集需要真实模型密钥"。本轮**核实后认为该前提对本数据集不成立**，
三项全部归为"可用固定数据离线验证"，**没有一项真正依赖模型，也没有一项是产品缺陷**：

- 三项的共同根因是**验收栈从未生成演示教学数据集**（种子只建学生/画像/目录，不建学习记录）；
- 关键证据：`GrowthTrendChart` 在**只有 1 个**趋势点时仍渲染 testid，故"元素不存在"意味着
  李明的学习证据事件数为 **0**，而不是渲染问题；
- 修复：新增 `scripts/grant/e2e/build_demo_dataset.py`（**离线、确定性、无密钥**），
  复用运维工具**同一份** plan 与路由代码，把回放分数存为带标签的 `rule_fallback`
  （正是学生徽标与研究 CSV 读取的口径）；它是运维工具的**严格反函数**——
  **配了模型就拒绝运行**，避免把规则回退数据误当 AI 数据。

结果：既有 Playwright 套件 **26/3/11 → 40/0/0**；11 个跳过中 9 个现在真实运行
（含把"无 JWT_SECRET 时失败关闭"从跳过改为起一个无密钥前端真实观察 503）。
**真实外部依赖项**（`E2E_EXPECT_REAL_AI=1` 的真实 provider 路径）**如实记录而非静默跳过**，
并在文档中给出人工需执行的命令。详见 `R9_PLAYWRIGHT_CLASSIFICATION.md`。
