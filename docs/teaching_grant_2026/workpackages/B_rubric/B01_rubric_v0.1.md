## 1. 这份量表是什么

ClinPath 的病例训练要求学生按五个推理阶段逐步作答：

| 阶段 key | 阶段名称 | 学生要回答的问题 |
| --- | --- | --- |
| `key_information` | 关键信息提取 | 哪些阳性、阴性和异常检查真正关键？ |
| `initial_diagnosis` | 初步诊断及依据 | 首要诊断是什么，依据是什么？ |
| `differential_diagnosis` | 鉴别诊断 | 还要排除什么，用什么证据排除？ |
| `examination` | 进一步检查 | 还缺哪些检查，每项解决什么临床问题？ |
| `treatment` | 治疗方案 | 怎么治，依据、风险和监测是什么？ |

本量表把这五阶段的表现映射为六个维度，每个维度给一个 **0–100 的形成性分数**，
再按权重合成一个 0–100 的加权总分。量表的目的是让教师对“临床推理质量”
形成可讨论、可复核的共同语言，而不是把学生变成一个小数点。

### 1.1 六个维度与权重

| 维度 key | 中文名 | 权重 |
| --- | --- | ---: |
| `medical_knowledge` | 医学知识 | 10% |
| `key_information` | 关键信息 | 20% |
| `differential_diagnosis` | 鉴别诊断 | 25% |
| `evidence_integration` | 证据整合 | 15% |
| `clinical_decision` | 临床决策 | 20% |
| `evidence_based_medicine` | 循证安全 | 10% |
| **合计** | | **100%** |

权重体现的是本科见习阶段的教学重点：鉴别诊断与临床决策合计 45%，
因为“想到什么、怎么排除、下一步做什么”是临床推理的核心；单纯的疾病名词
记忆只占 10%。

## 2. 与平台现有实现的关系（必须先读）

本量表是 **研究/教学评价提案**，不是对平台现有打分逻辑的复述。当前仓库中：

1. `backend/app/services/scoring_llm.py` 的 `WEIGHTS` 为
   `20 / 20 / 20 / 15 / 15 / 10`，与本量表的 `10 / 20 / 25 / 15 / 20 / 10` **不同**。
2. `backend/app/services/competency_projector.py` 的 `confirmed_total()` 对六维取
   **算术平均**，不是加权和。
3. 因此，**平台当前返回的 `total_score` 不是 `rubric-v0.1` 总分**。

在平台完成权重对齐之前：

- 任何标注为 `rubric-v0.1` 的总分，必须由 `scripts/grant/rubric_agreement.py`
  从六个维度原始分**离线计算**（`Σ(score × weight%)`），不得直接取平台 `total_score`。
- 教师复核页面显示的 AI/规则总分只能作为参考，不能当作本量表总分。
- 权重对齐属于一次独立的、需要测试与迁移说明的代码变更；本次工作包
  **没有**修改平台打分逻辑，也不应被描述为已对齐。

工作包 D 的合成数据生成器恰好使用了与本量表一致的
`10 / 20 / 25 / 15 / 20 / 10`，但那是**模拟数据生成参数**，不构成平台实现，
也不能用来证明平台已经按本量表计分。

## 3. 六个维度的定义、证据来源与评分锚点

评分锚点采用三段式：**低 0–39 / 中 40–69 / 高 70–100**。
锚点是**标准参照**（criterion-referenced），即对照行为描述判断，
不是把学生和同班同学比较。每个维度给出 2–3 条可观察的行为描述，
供两位评分者独立判断后讨论。

> 通用规则：**空白作答不等于 0 分**。若某阶段没有作答，表示“未提供证据”，
> 该维度不评分、总分留空；不得用 0 分代替缺失。

### 3.1 医学知识（`medical_knowledge`，10%）

**定义**：在具体病例中调用风湿免疫学核心知识（疾病谱、分类/诊断标准、
病理生理、药物机制）来解释表现的能力。它衡量的是“用知识解释这个病人”，
不是名词记忆量。

**证据来源**：主要来自 `initial_diagnosis`；`differential_diagnosis` 中体现的
疾病知识作为次要证据；`examination` 与 `treatment` 中的机制性表述可作佐证。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 只给出模糊病名或错误归因（如把所有多系统表现笼统归为“免疫病”）；不能区分分类标准与临床诊断；关键概念（如自身抗体阳性的意义）明显错误。 |
| 中 | 40–69 | 能提出合理的工作诊断并给出部分依据；知道主要分类标准，但套用生硬或忽略前提；对阴性结果、抗体假阳性的意义解释有限。 |
| 高 | 70–100 | 能把症状、实验室与器官受累整合成病理生理链条；准确区分分类标准、临床诊断与活动度/损伤；能说明知识的适用边界和当前不确定性。 |

### 3.2 关键信息（`key_information`，20%）

**定义**：从病史、查体、检验中提取关键阳性、关键阴性和危险信号，
并区分主次的能力。

**证据来源**：主要来自 `key_information` 阶段；`initial_diagnosis` 中
“依据”部分的取材质量作为补充证据。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 罗列大量无关信息或遗漏关键阳性；不识别器官威胁等危险信号；把阴性/正常结果当作“没有信息”。 |
| 中 | 40–69 | 能列出主要阳性表现，但关键阴性或危险信号不全；信息主次不够清楚，部分关键检查结果未被使用。 |
| 高 | 70–100 | 系统覆盖关键阳性、关键阴性和器官威胁信号；明确指出哪些信息会改变诊断或处置；能说出目前还缺哪些信息。 |

### 3.3 鉴别诊断（`differential_diagnosis`，25%）

**定义**：提出合理的鉴别列表，按可能性与风险排序，并用支持/反对证据
论证、说明如何排除的能力。

**证据来源**：主要来自 `differential_diagnosis` 阶段；
`examination` 阶段中“用哪项检查排除哪项鉴别”的表述作为验证策略证据。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 鉴别列表过短或离题；只列病名不给依据；漏掉最危险、最不能漏诊的可能（如感染、肿瘤、HLH）。 |
| 中 | 40–69 | 能列出常见鉴别并给出部分支持点，但缺少反证或排序理由；对“目前不能排除”的处理含糊。 |
| 高 | 70–100 | 覆盖感染、肿瘤、其他结缔组织病等关键类别并按风险排序；对每项给出支持与反对证据；说明用何种检查排除，以及排除后仍剩多少不确定性。 |

### 3.4 证据整合（`evidence_integration`，15%）

**定义**：把多条证据（症状、体征、实验室、影像、病程）组织成
支持/反对某个假设的论证，并处理矛盾信息的能力。

**证据来源**：`key_information` + `initial_diagnosis` + `examination`
三个阶段的论证结构；不要求单独一个阶段。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 证据与结论脱节；只堆砌阳性结果；忽略矛盾或阴性证据；结论明显超出所给证据。 |
| 中 | 40–69 | 能引用支持证据，但反证和矛盾处理不足；结论略强于证据，或把“相关”说成“确诊”。 |
| 高 | 70–100 | 明确区分支持与反对证据；能解释矛盾结果（如抗体阳性但临床不典型）；结论强度与证据强度匹配，并保留不确定性。 |

### 3.5 临床决策（`clinical_decision`，20%）

**定义**：基于问题表征选择检查与治疗，说明每项决策要解决的临床问题、
时机、风险与监测计划的能力。

**证据来源**：`examination` + `treatment` 两个阶段。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 检查/治疗与问题不匹配；无优先级；遗漏器官威胁的紧急处理（如快速进展性肾损伤、肺泡出血）。 |
| 中 | 40–69 | 能给出常规检查和初始治疗，但优先级、时机或个体化不足；监测计划笼统（只说“定期复查”）。 |
| 高 | 70–100 | 按临床问题分层安排检查，说明每项如何改变决策；治疗与器官受累和患者风险匹配；给出疗效与不良反应监测，以及升级/降级条件。 |

### 3.6 循证安全（`evidence_based_medicine`，10%）

**定义**：决策有指南/证据依据并说明推荐强度与适用边界；
主动识别并规避可预防伤害的能力。

**证据来源**：主要来自 `treatment`（依据、风险、监测）；
`examination` 中“为什么做这项检查”的合理性作为补充；
全篇的安全相关表述都计入。

| 水平 | 分值 | 行为描述 |
| --- | --- | --- |
| 低 | 0–39 | 无依据或依据错误；免疫抑制前不筛查感染；无监测计划；存在明确、可预防的安全隐患。 |
| 中 | 40–69 | 提到指南或常规做法但未说明适用条件；有监测但不够具体；对药物风险只作泛泛提醒。 |
| 高 | 70–100 | 引用指南/证据并说明版本与适用边界；治疗前完成感染、器官功能与用药禁忌评估；给出可执行的安全监测与随访计划。 |

## 4. 加权总分与边界条件

### 4.1 总分公式

设六个维度分数为 `s_i`，权重为 `w_i`（`Σ w_i = 1.00`），则：

```text
total = Σ (s_i × w_i)
```

按本量表权重展开：

```text
total = 0.10×医学知识 + 0.20×关键信息 + 0.25×鉴别诊断
      + 0.15×证据整合 + 0.20×临床决策 + 0.10×循证安全
```

`total` 与六个维度分数均保留 **1 位小数**，采用**四舍五入**（half-up）。
注意：Python 内置 `round()` 使用银行家舍入（`round(70.25, 1)` 得 `70.2`），
与本节不一致；`B04` 脚本用 `Decimal(..., ROUND_HALF_UP)` 实现，已写入自检。

计算示例：六维为 `80, 70, 60, 75, 65, 90` 时，

```text
0.10×80 + 0.20×70 + 0.25×60 + 0.15×75 + 0.20×65 + 0.10×90
= 8 + 14 + 15 + 11.25 + 13 + 9 = 70.25 → 70.3
```

### 4.2 边界条件（评分前必须确认）

1. **分值域**：每个维度为 `[0, 100]`。教师评分建议用整数；平台内部可存 1 位小数。
2. **完整性**：六个维度必须齐全才能计算总分。缺任一维度时总分**留空**，
   不得用 0 分补齐，也不得按剩余维度重新归一化。
3. **权重和**：六个权重之和必须恰好为 1.00。任何改动都要升版本号。
4. **标准参照**：锚点描述的是“这份作答表现出什么”，不是“在班里排第几”。
5. **一份作答一个分数**：同一份作答的同一维度只能有一个最终分。
   评分者之间的分歧记录在 `remarks`，保留原始分，不覆盖、不改写。
6. **安全底线**：若 `循证安全` 存在以下任一情况——免疫抑制前未筛查感染、
   未评估器官威胁、无监测/随访计划——该维度**不得高于 39 分**。
   v0.1 不因此自动封顶总分；是否封顶由教师集体讨论后另行规定。
7. **空白 ≠ 0**：空白表示“未提供证据”，按缺失处理，不评分。
8. **降级标注**：若平台评分来自规则回退（`rule_fallback` / `degraded`），
   必须在记录中保留该标记；不得把规则输出当作 AI 评分或教师评分。

### 4.3 版本规则

- 当前版本字符串：`rubric-v0.1`。
- 以下任一改动必须升版本号（例如 `rubric-v0.2`）：维度增删、权重调整、
  锚点行为描述修改、边界条件修改。
- 历史评分记录保留其评分时的 `rubric_version`，不得用新版本回填旧记录。
- 版本升级需要重新进行评分者校准；不同版本的一致性数据不得合并报告。

## 5. 内部形成性评分 vs 独立研究主结局

这是本工作包最容易被混淆、也最不能含糊的一点。

| 对比项 | 内部形成性评分 | 独立研究主结局 |
| --- | --- | --- |
| 目的 | 给学生反馈、驱动推荐与教学干预 | 回答研究问题、估计教学效果 |
| 产生者 | 平台 AI 或规则回退 | 两位**真实、盲法**的评分者 |
| 发生时机 | 学生提交学习事件时 | 离线、评分者看不到平台分数 |
| 是否盲 | 否（学生与教师都能看到） | 是（评分者只看到作答文本） |
| 是否回写能力画像 | 是（`reproject_competencies`） | 否（只进研究数据集） |
| 是否可用于研究主结局 | **否** | 是 |
| 证据文件 | `ai_invocations` 审计、`Score`、`TeacherScoreReview` | `B03_rating_template.csv` → `B04` 分析 |
| 允许的表述 | “本次训练的形成性反馈” | “两位真实评分者对模拟作答的独立评分” |

### 5.1 平台内“教师复核确认”不是盲法独立评分

教师在平台内执行“复核确认”（`POST /api/teacher/reviews`）时：

- 教师能看到 AI/规则给出的六维分数；
- 确认结果会写入 `TeacherScoreReview`，并触发 `reproject_competencies()`，
  **回写学生的学习者能力画像**；
- 因此它是**教学修正**，不是盲法独立评分，**不能**作为研究主结局，
  也不能用来计算评分者一致性。

盲法研究评分必须留在离线模板（B03）中，直到平台未来提供真正的盲法模式。
详见 `B03_export_template.md` 第 4 节。

### 5.2 模拟评分者不是教师

工作包 D 的两位“计算机模拟评分者”标记为 `SIMULATED_NOT_HUMAN`。
它们生成的是模拟数据，**不是真实教师**，不得改标为教师，
也不得用它们计算“真实教师一致性”。B04 的演示输出只用于证明脚本可运行，
不得引用为研究结果。

## 6. 评分流程（真实教师盲评）

1. 教师阅读本量表与锚点，完成一次校准讨论（可使用 B02 的模拟作答）。
2. 两位教师**各自独立**对同一批作答评分，期间不讨论、不看对方分数、
   不看平台 AI 分数。
3. 使用 `B03_rating_template.csv` 填写；`rater_id` 使用匿名编号，
   不写姓名；`review_date` 使用 ISO 日期（`YYYY-MM-DD`）。
4. 提交后由研究协调人运行 `scripts/grant/rubric_agreement.py`。
5. 只有在真实评分到位后，才允许报告一致性；报告必须注明
   `rubric_version`、评分者人数、样本量和是否盲法。
6. 分歧较大的条目先讨论、再决定是否修订量表；修订即升版本号。
