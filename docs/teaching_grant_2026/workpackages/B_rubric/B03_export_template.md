# B03 评分导出模板与盲评流程

| 项目 | 内容 |
| --- | --- |
| 文档编号 | B03 |
| 量表版本 | `rubric-v0.1` |
| 空白表 | `B03_rating_template.csv`（32 行 = 16 份样本 × 2 个真实评分者槽位） |
| 分析用空白表 | `B04_agreement_template.csv`（同结构，供 `B04` 脚本直接读取） |
| 机读列定义 | 本文件第 2 节 |

> **状态声明**：本模板是空白表。其中没有任何真实评分、真实姓名或真实日期。
> `rater_id` 与 `review_date` 必须由真实评分者本人填写。

---

## 1. 这份模板解决什么问题

研究需要的是**两位真实评分者在互不知情的情况下对同一批作答给出的独立分数**。
平台内没有这样的流程，所以研究评分必须离线完成，再导入分析脚本。

本模板就是那个离线的、可审计的载体：一行 = 一位评分者对一份作答的完整评分。

## 2. 列定义（顺序即导出顺序）

| 列名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sample_id` | string | 是 | 样本编号，`B2-001` – `B2-016`，与 `B02_sample_answers.csv` 一一对应 |
| `case_id` | string | 是 | 病例编号，`CASE-T01` – `CASE-T04`、`CASE-A01` – `CASE-A02` |
| `rubric_version` | string | 是 | 固定为 `rubric-v0.1`；量表升版后必须同步修改，不得回填旧记录 |
| `rater_id` | string | 是 | 评分者匿名编号（如 `RATER-01`）。**不得填写姓名、工号或邮箱** |
| `rater_origin` | enum | 是 | `REAL_BLINDED_RATER`。禁止填写 `SIMULATED_NOT_HUMAN` 以外的模拟来源；模拟评分者数据只允许出现在 B04 的演示文件中 |
| `medical_knowledge` | number 0–100 | 是 | 医学知识 |
| `key_information` | number 0–100 | 是 | 关键信息 |
| `differential_diagnosis` | number 0–100 | 是 | 鉴别诊断 |
| `evidence_integration` | number 0–100 | 是 | 证据整合 |
| `clinical_decision` | number 0–100 | 是 | 临床决策 |
| `evidence_based_medicine` | number 0–100 | 是 | 循证安全 |
| `total` | number 0–100 | 是 | 加权总分，`Σ(score × weight%)`，保留 1 位小数。见 `B01` 第 4.1 节 |
| `review_date` | date | 是 | 实际评分日期，ISO `YYYY-MM-DD` |
| `remarks` | string | 否 | 分歧、存疑条目或对量表的意见。可含逗号，导出时按 CSV 规则加引号 |

**列顺序必须与上表完全一致。** 下游脚本按列名读取，不依赖位置，
但导出规范以本表为准，避免不同教师产出不同形状的文件。

### 2.1 空白表的结构

`B03_rating_template.csv` 共 32 行数据：

```text
B2-001  → 第 1 行（评分者槽位 1）、第 2 行（评分者槽位 2）
B2-002  → 第 3、4 行
...
B2-016  → 第 31、32 行
```

同一 `sample_id` 的两行在空白表中完全相同（`rater_id` 为空），
靠行序区分槽位。评分者填写 `rater_id` 后，两行即可区分。
**不要删除行**：脚本按样本配对，缺行会导致该样本被排除并给出提示。

## 3. 填写与提交

1. 每位评分者拿到一份**独立副本**，只填写自己的两列身份信息与六个维度分数。
2. 先填六个维度，再按 `B01` 第 4.1 节计算 `total`，**不要**使用平台总分。
3. 提交前自查：
   - 六个维度是否都在 `[0, 100]`；
   - `total` 是否等于加权和（容差 ±0.05）；
   - `rater_origin` 是否为 `REAL_BLINDED_RATER`；
   - `review_date` 是否为真实日期。
4. 两位评分者的文件由研究协调人合并成一份，再运行 `B04` 脚本。
5. 原始文件保留，不覆盖；修订另存并注明原因。

## 4. 重要限制：平台“复核确认”不是盲法独立评分

这一节是本工作包最容易被误用的地方，必须原样保留。

平台教师端的“复核确认”（`POST /api/teacher/reviews`，页面在
`/teacher/score-review`）**不能**当作盲法独立评分，原因是：

1. **不盲**：教师复核时能看到 AI/规则给出的六维分数和总分，
   评分已经被锚定；
2. **会回写能力画像**：确认结果写入 `TeacherScoreReview`，并触发
   `reproject_competencies()`，**改变学生的学习者能力画像**和后续推荐；
3. **目的不同**：它是教学修正（教师对机器评分做最终裁定），
   不是研究测量；
4. **不可分离**：一旦回写，就无法再声称评分者“独立于平台”。

因此：

- 平台内复核数据**不得**进入 `B03`/`B04` 的研究评分数据集；
- 平台内复核数据**不得**用于计算评分者一致性；
- 盲法研究评分**必须留在离线模板**中，直到平台未来提供真正的
  盲法模式（评分者看不到 AI 分数、评分不回写画像、有独立审计轨迹）。
- 该盲法模式目前**不存在**，本工作包也没有实现它。

`B01` 第 5 节给出了内部形成性评分与独立研究主结局的完整对照表。

## 5. 与工作包 D 模拟评分者的关系

工作包 D 的 `assessments_SYNTHETIC.csv` 中有两位“计算机模拟评分者”，
标记为 `rater_origin=SIMULATED_NOT_HUMAN`。它们：

- 不是真实教师，不得改标；
- 不得填入 `B03_rating_template.csv` 的 `rater_id`；
- 只能用于 `B04_simulated_rater_demo.csv` 这类演示输入，且输出必须标注
  “模拟评分者示例｜SIMULATED_NOT_HUMAN｜不是真实教师一致性”。

## 6. 数据治理

- 评分文件按 `REAL_CONSENTED` 类数据管理：只存放在受控目录，
  不进仓库、不进演示数据集、不进入学生可见页面。
- 仓库中只提交**空白模板**与本说明；真实评分文件由研究协调人保管。
- `rater_id` 与研究编号的对应表单独保存，与评分文件分离，降低重识别风险。
- 任何导出、截图或报告都必须保留 `rubric_version` 与评分者人数。
