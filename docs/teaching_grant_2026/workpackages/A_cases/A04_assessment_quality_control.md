### 1.2 判断：两例难度可比吗？

**结论：不可比。CASE-A02 明显难于 CASE-A01。**

证据（均可回溯到卡片原文）：

1. **卡片自评难度不同**：A01 头部标注"难度：中等"、"适用学段：本科临床见习（第2–3阶段）"；A02 头部标注"难度：进阶"、"适用学段：本科临床见习（第3阶段：鉴别诊断 / 临床决策入门）"。`A01_case_index.md` 的病例总表同样记为"中等"与"进阶"。
2. **推理性质不同**：A01 的核心是**单一分类标准**（2010 ACR/EULAR）的边界计分，学生只需证明"入口满足但总分 5 < 6"；A02 的核心是**跨四大类**（感染 / 肿瘤 / 自身免疫 / 自身炎症）的排除，并叠加一个急症（MAS/HLH）的识别。
3. **危险信号数量与性质不同**：A01 §5 为 5 条（多为"提示进一步检查"）；A02 §5 为 7 条，其中 MAS/HLH、DIC、呼吸衰竭属于需要**立即处理**的急症。
4. **检查深度不同**：A02 要求学生考虑骨髓穿刺/活检、sCD25、NK 细胞活性等血液科层面检查；A01 的检查清单停留在风湿科常规 + 治疗前筛查。
5. **治疗复杂度不同**：A01 的治疗原则本质是"**不过度治疗 + 随访**"；A02 要求分层治疗并写出 MAS 的紧急处理与监测计划。

**因此，若两例难度差在时间点上固定（所有学生 D1 都用 A01、D6 都用 A02），前后测差会混入病例难度差，主结局会被系统性偏倚。** 这正是第 2 节需要题本顺序平衡的原因。

| 选项 | 做法 | 代价 |

## 2. 整批分配下的题本顺序平衡

### 2.1 为什么需要平衡

- 研究设计为**两组前后测**：D1（第 1 天）与 D6（第 6 天）各做一次独立标准化病例，主要结局是 **D6 总分**（以 D1 总分为协变量）。
- 分组单位是**整批**：一个批次的 7 名学生整体进入 ClinPath 或常规 CBL 教学组，**批次内的学生不拆分到不同教学组**。
- 两例难度不同（§1.2）。若所有学生"D1 一律用 A01、D6 一律用 A02"，则"D6 − D1"同时包含**学习增益**与**两例难度差**，且该难度差与时间点完全共线，无法从数据中分离。
- 因此需要**题本顺序平衡**：在**不改变批次所属教学组**的前提下，让两例在两个时点上、在批次内部与批次之间相互抵消。

### 2.2 设计：整批分配 + 批内顺序随机（counterbalanced crossover）

- **教学组（整批）**：3 批 ClinPath、4 批 CBL，预先固定，从 C(7,3)=35 中随机产生（见 `E5_01` §3 与 `E5_02`）。
- **题本顺序（批内）**：在**每一个完整批次内部**，把 7 名学生随机分到顺序 X 与顺序 Y：
  - **顺序 X**：D1 = CASE-A01，D6 = CASE-A02
  - **顺序 Y**：D1 = CASE-A02，D6 = CASE-A01
- 每名学生在 D1 与 D6 各做**一套不同**病例；同一批次内 7 人按 **4/3 或 3/4** 分配（7 为奇数，无法精确对半）。
- **批内顺序随机不改变该批次的教学组**：一个 ClinPath 批次无论其内部 X/Y 如何分配，仍是 ClinPath 批次。X/Y 的随机化与批次臂别是**两个相互独立的因素**。

### 2.3 X/Y 分配表与算术

**总体算术。** 全研究 7 批 × 7 人 = **49 人**，其中 ClinPath **3 批 × 7 = 21 人**、CBL **4 批 × 7 = 28 人**。

- 总体 49 为**奇数** → X 与 Y 无法精确相等（需各 24.5），最接近只能是 **24 / 25**（相差 1）。
- CBL 臂 28 为**偶数** → **可以精确平衡**：**14 / 14**。
- ClinPath 臂 21 为**奇数** → 无法精确平衡（需各 10.5），最接近只能是 **10 / 11**（相差 1）。
- **结论：由于 21 与 49 均为奇数，"两臂各自精确平衡 + 总体精确平衡"三者同时成立是不可能的。** 可达到的最接近方案是：**CBL 精确 14/14，ClinPath 最接近 10/11，总体最接近 24/25**（总偏离完美平衡 1 人）。

**构造方法。** 记每个批次为"4X 型"（批内 4 人顺序 X、3 人顺序 Y）或"3X 型"（3 人顺序 X、4 人顺序 Y）：

- CBL 臂：**2 个 4X 型 + 2 个 3X 型** → X = 2×4 + 2×3 = **14**，Y = 2×3 + 2×4 = **14** ✓（精确平衡）
- ClinPath 臂：**1 个 4X 型 + 2 个 3X 型** → X = 4 + 3 + 3 = **10**，Y = 3 + 4 + 4 = **11** ✓（最接近）
- 合计：X = 14 + 10 = **24**，Y = 14 + 11 = **25**，24 + 25 = **49** ✓

**逐批分配表**（批次编号仅为示意；哪个批次属于 ClinPath 由 C(7,3)=35 的随机抽取决定，此处假设抽中 B1/B3/B5）：

| 批次 | 教学组（整批固定） | 顺序 X（D1=A01, D6=A02） | 顺序 Y（D1=A02, D6=A01） | 小计 |
| --- | --- | --- | --- | --- |
| 批次 1 | ClinPath | 4 | 3 | 7 |
| 批次 2 | CBL | 4 | 3 | 7 |
| 批次 3 | ClinPath | 3 | 4 | 7 |
| 批次 4 | CBL | 3 | 4 | 7 |
| 批次 5 | ClinPath | 3 | 4 | 7 |
| 批次 6 | CBL | 4 | 3 | 7 |
| 批次 7 | CBL | 3 | 4 | 7 |
| **合计** | **3 ClinPath / 4 CBL** | **24** | **25** | **49** |

**臂别 × 顺序交叉表**（四个单元格合计）：

| | 顺序 X（D1=A01，D6=A02） | 顺序 Y（D1=A02，D6=A01） | 合计 |
| --- | --- | --- | --- |
| ClinPath | 10 | 11 | 21 |
| CBL | 14 | 14 | 28 |
| **合计** | **24** | **25** | **49** |

**镜像方案。** 把 ClinPath 臂中"4X 型"的那一批改为"3X 型"（即 ClinPath 2 个 4X 型 + 1 个 3X 型），得到 ClinPath X/Y = **11/10**、总体 **25/24**；CBL 仍为 14/14。两镜像方案统计上等价，**在 D1 之前用一次记录在案的随机（如掷币）确定采用哪一个**，并把结果写入分配记录。

> **分配记录**（D1 前完成）：批次臂别（3 ClinPath / 4 CBL）及其随机种子、每批 X/Y 名单、采用主方案还是镜像方案。分配记录一经生成即固定，不因中途脱落而更改。

### 2.4 代价与统计影响

- **代价 1（单元格人数下降）**：批内 4/3 或 3/4 分配后，每臂合计为 21 / 28；交叉后 4 个单元格为 10 / 11 / 14 / 14。若中途有学生脱落，单元格人数下降，按 ITT 处理缺失，**不补人**。
- **代价 2（每名学生在 D1 与 D6 做的是不同病例）**：因此"D6 − D1"同时含"学习增益"与"两例难度差"。题本顺序平衡把难度差在**批内、臂间、批次间**抵消，但**不减小方差**。是否在主模型中显式加入"D6 所用病例"指示变量以吸收残余难度差，由 SAP（`E5_02`）决定；若加入，须在预注册中固定，不得在看到结果后追加。
- **代价 3（自由度）**：在 49 人、7 批次的规模下，任何"顺序 × 组别"交互的每格人数都不足，只能作**描述性展示**，不作推断。

### 2.5 其他方案（不推荐，供对照）

- **方案 a（两时点同病例）**：每名学生在 D1 与 D6 做**同一**病例，由批次层面平衡（一半批次用 A01、一半用 A02）。缺点：病例与批次共线，且同一学生重复做同一病例存在记忆 / 练习效应。**不推荐。**
- **方案 b（固定顺序，不反平衡）**：所有学生 D1=A01、D6=A02。若两例难度差对两组是**可加**的，则组间比较仍可部分抵消；但若两例对两组的敏感度不同（例如 A02 更依赖综合推理，ClinPath 组在 A02 上获益更大），则产生"顺序 × 组别"交互偏倚。**不推荐。**

**采用的设计为 §2.2 的整批分配 + 批内题本顺序平衡（§2.3 分配表）。**

### 3.4 考核访问隔离要求（新增，**必须实测验证**）

**原则**：D1 / D6 独立考核**不得依赖学生可自由浏览的公开训练病例列表**。考核病例必须**只能通过受控路径**到达，不能靠学生自行浏览病例库进入。

**平台现状（只读核对，`backend/app/`）**：

- `GET /api/cases`（`backend/app/routes/cases.py:12–14`）对**任何已登录用户**返回**全部**病例的 `serialize_case_summary`，字段含 `title`、`disease_category`、`difficulty`、`chief_complaint`、`learning_objectives`（`backend/app/services/serializers.py:116–124`）。**学生端可枚举到病例库中的全部病例标题与主诉。**
- `GET /api/cases/{case_id}`（`cases.py:17–22`）对学生调用 `serialize_case_for_student`，下发 `id/title/disease_category/difficulty/learning_objectives/chief_complaint/history/physical_exam/lab_results/imaging`（`serializers.py:100–113`）——虽不下发标准诊断，但**病例全文与主诉可被按 ID 读取**。
- 前端学生端**没有**独立的病例列表页（`frontend/app/(main)/student/` 下无 `cases` 列表页），但存在 `/student/case/[caseId]` 详情页，可按 ID 直接进入；**只要病例存在于库中且 ID 可枚举，隔离即被破坏**。
- `Case` 表无 `assessment_only` / `review_status` 字段，平台层**无法区分**训练病例与考核病例。

**要求的访问隔离（须在开放正式考核之前落实）**：

1. **不入列表**：两份考核病例（及与其同病种的种子病例，见 §3.3）**不得**出现在 `GET /api/cases` 的学生可见结果中，也不得进入任何训练任务或个性化推荐路径。
2. **受控发放**：考核作答只能通过**受控入口**发放——由教师在 D1 / D6 按批次与分配名单下发考核病例 ID 或一次性访问链接，学生**不能**通过自行浏览病例库进入考核病例。
3. **按批次与时间窗开启**：考核入口按批次与考核时段开启（D1、D6 各自的作答窗口），窗口结束即关闭。
4. **可核验区分**：训练病例与考核病例在平台侧以**可核验方式**区分（如专用分类标记 / 独立数据集 / 访问控制列表），**不能仅靠文档约定**。
5. **验证留痕**：上述隔离必须**由平台负责人用真实学生账号实测验证**（尝试枚举并访问考核病例，确认不可达），并留存验证记录。

### 3.5 正式考核开放的前置条件（**两项均为 precondition，非形式程序**）

正式 D1 / D6 考核在下列**两项全部满足之前不得开放**：

- **条件一（教师审核）**：CASE-A01、CASE-A02 两份考核病例已由**两位真实教师**独立审核并签字（校准表 `final_approval` 由 `PENDING_REAL_REVIEW` 改为通过），六维评分量表已完成校准。
- **条件二（访问隔离验证）**：§3.4 的考核访问隔离已由平台负责人**实测验证并留痕**（用学生账号确认考核病例不可枚举、不可自行进入）。

任一条件未满足，正式考核不得开放。这两项与 §4 的评分者校准共同构成 D1 之前的方法学准备，**不是可以事后补办的手续**。

## 4. 盲评工作量与统一裁决规则

### 4.1 工作量估算

| 项目 | 数值 |
| --- | --- |
| 学生数 | 49 |
| 每生时点数 | 2（D1、D6） |
| 作答份数 | 49 × 2 = **98** |
| 评分者数 | 2（真实教师 A、B） |
| 总评分次数 | 98 × 2 = **196** |
| 每位评分教师承担 | **98 次** |
| 单次评分耗时（估计） | 8–15 分钟（中位 10 分钟） |
| 每位评分教师总量 | 10 分钟/次：98 × 10 = 980 分钟 ≈ **16.3 小时**；区间 **13.1–24.5 小时/人/年** |

> 单次耗时估计依据：六维量规、含鉴别排序与证据整合的完整作答，评分者需对照标准答案要点逐维打分。
> 注意：**D1 与 D6 的作答对同一位评分教师均需独立评分**，故 196 次包含两个时点；D1 的成绩由教师在 D6 之后**统一评分**（`E5_01`/`T3`），不假设其已进入 D1 当天的能力画像。

### 4.2 7 天轮转内的可行性

- 按批次摊分：每批 7 人 × 2 时点 = **14 份/评分教师**；14 × 10 分钟 ≈ **2.3 小时**（区间 1.9–3.5 小时）。
- 在 7 天轮转内**可行**：D6 结束后、第 7 天及之后完成该批 14 份评分即可，建议分 2–3 个时段（每段 ≤ 1 小时）。
- 全年累计 13–25 小时/评分教师，分摊到 7 个批次。
- **可行性前提**：(a) 作答去标识并打乱；(b) 按批次及时评阅；(c) 量表在 D1 前完成校准（见 `E5_02` §7.6 的校准 ICC）。

### 4.3 具体工作流

1. **收集**：每批 D1（第 1 天）与 D6（第 6 天）的学生作答。
2. **去标识**：去掉姓名/学号/组别/时点标签，改为随机编号（如 `B3-S07-R1`）；**D1 与 D6 作答混合、随机排序**，使评分者对时点设盲。
3. **分发**：把该批 14 份（7 生 × 2 时点）同时交给评分教师 A、B，各自独立按同一六维量规评分。
4. **记录**：填入 `B03_rating_template.csv` / `B04_agreement_template.csv`，写 `rater_A_total`、`rater_B_total`、`rater_agreement_delta = |A − B|`。
5. **一致性**：每批计算 ICC(2,1)。
6. **分歧**：`|A − B| > 10` 分（总分 0–100）→ 交第三位教师裁决（见 §4.4）。
7. **定稿**：写入 `independent_total`（主结局 Y）。

### 4.4 统一裁决规则（D1 与 D6 适用**同一条规则**，须在 D1 前固定并写入 SAP）

**唯一的阈值与唯一的最终分规则如下，D1 与 D6 不再有第二套口径：**

- **触发条件（唯一）**：`|A − B| > 10.0 分`（总分 0–100），即差 **11 分及以上**。`≤ 10 分`时不启用第三评分者。
- **最终分（唯一）**：取 A、B、C 三人中**"最接近的两人的均分"**：
  - 若 C 与 A 最接近 → final = (A + C) / 2；
  - 若 C 与 B 最接近 → final = (B + C) / 2；
  - 若 |A − C| = |B − C| → final = (A + B + C) / 3。
- **同一规则应用于两个时点**：D1 与 D6 的评分分歧都用上述阈值与最终分规则，不因时点不同而不同。

**为什么选"最接近两人均分"而不是"直接取 C 分"**：

1. 使用了全部三次评分，不丢弃 A、B 的信息；
2. 对称：A、B 地位相同，不因谁先评分而不同；
3. 自动降低离群评分的权重，减小测量方差，提高主结局信噪比；
4. 确定性强、可复算，便于留痕与预注册。

**口径统一（必须执行）**：`E5_02` §6.1 曾写"建议 **≥ 10 分**（待确认）"，本文与 SAP 必须统一为"**> 10 分**"（即差 11 分及以上触发），并写入 SAP 与数据字典（`rater_agreement_delta`、`adjudication_used` 字段已存在）。SAP 的定稿由 `E5_02` 负责人完成；本文与 SAP 在 D1 前必须逐字一致。

### 4.5 第三评分者的使用

- **仅用于分歧**，不参与常规评分。
- **工作量**：若分歧率 10–20%，则每年约 196 × 10–20% ≈ **20–39 次**第三评分（每次 10 分钟 → 约 3–6.5 小时/年）。
- **人选**：可由第三位风湿免疫科带教老师担任。申请人已确认"可安排至少 2 位带教老师"，**第三位是否可用需确认**。
- **若第三位教师不可用**：退而求其次为"分歧案例由 A、B 协商一致"，但会削弱盲法，**不推荐**。
